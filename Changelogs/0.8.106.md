# 0.8.106

The first release that ships `objc-section` prebuilt: a universal (x86_64 + arm64) macOS binary is attached, so the tool no longer has to be built from source. On top of `0.8.105` it adds ObjC API diffing (freeze a binary's API as a baseline, diff two versions, or follow every declaration across many) and a library API that tells whether a class or an ivar is exported.

## What's new

- **Prebuilt `objc-section`**: download `objc-section-macos-universal.zip` from this release and unzip it. The binary is ad-hoc signed, not notarized; if macOS blocks a copy downloaded through a browser, run `xattr -d com.apple.quarantine objc-section`.
- **`objc-section snapshot`** indexes a Mach-O file, a fat binary or an image in a dyld shared cache, and writes its ObjC API as a JSON baseline: `objc-section snapshot <file> --label 26.0 -o baseline.json`. Later comparisons read the JSON and need neither the original binary nor another indexing pass.
- **`objc-section diff <old> <new>`** reports classes, protocols and categories, with their methods, properties, ivars, protocol adoptions and superclass, as added / removed / modified, and gives a breaking or backward-compatible verdict. Either side can be a binary or a baseline. `--json` emits structured output, `--summary-only` prints the verdict alone, `--fail-on-breaking` exits nonzero for CI gating, and `-o` writes the report to a file.
- **`objc-section evolution <v1> <v2> …`** makes the same comparison across two or more versions in order and prints each declaration's lifeline. `--labels 17.0,18.0,26.0` names the versions, and the four options above apply here too.
- **`ObjCDiffing` library product**: the engine behind those three commands (`ObjCAPIDiffer`, `ObjCAPIEvolutionBuilder`, `ObjCAPISnapshotDocument`). `ObjCAPISnapshotBuilder` in `ObjCInterface` feeds it from a prepared `ObjCInterfaceIndexer`.
- **Export status of classes and ivars**: `ObjCExportIndex(machO:)` in `ObjCMetadataSource` answers `exportStatus(ofClassNamed:)` and `exportStatus(ofIvarNamed:inClassNamed:)` with `.exported`, `.notExported` or `.imageHasNoExportInformation`. The last one covers object files and static libraries, which have no export trie; never treat it as "not exported". Protocols and categories have no exported symbol, so there is no query for them. `objc-section` output does not change.

## Fixes

- `dump --sections` misread both natural spellings: `--sections classes protocols <file>` took the file path as a third section, and `--sections classes,protocols` was rejected. It now takes one comma-separated value, before or after the file path, and the space-separated form fails with a message pointing to the comma form. Present since `0.8.105`, the first release with `objc-section`.
- `dump` printed nothing and exited 0 in three different situations: the binary has no ObjC metadata, a kind named in `--sections` is empty, or `--filter` matched nothing. Each now writes one line to stderr naming the case, such as `no Objective-C metadata found in /bin/ls`. stdout and the exit code, still 0, are unchanged.

## Compatibility

- **Scripts** that pass space-separated values to `--sections` must switch to commas: `--sections classes,protocols`.
- `ObjCCategoryInfo.uniqueName` and `ObjCPropertyInfo.ivar` / `customGetter` / `customSetter` moved from `ObjCDeclarationRendering` to `ObjCMetadataSource`. Existing code keeps compiling, but a target that enables `MemberImportVisibility` (SE-0444) needs `import ObjCMetadataSource`, and a dependency on that product, wherever it uses them.
- Baselines carry `formatVersion` `1`. A baseline written with another format version is rejected with an error, not compared.
- Dependency requirements are unchanged. `dump` and `interface` output is unchanged apart from the stderr notes above.

## Requirements

- Swift 6.2+ and Xcode 26.0+ to build from source.
